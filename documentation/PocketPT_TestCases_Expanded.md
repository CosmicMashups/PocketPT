# PocketPT Test Cases - Expanded Descriptions

## Figure 1.1.4
### Test Case 4: Network Connectivity Issues

Test case four represents the comprehensive error handling mechanism implemented when network connectivity issues are detected during authentication operations. The system proactively checks network availability before initiating any authentication request, performing a connectivity test by attempting to resolve a well-known internet address. When network connectivity is unavailable or unstable, the application intercepts the failure condition and communicates the issue to the user through clear and actionable error messages. The primary error message displayed is "No internet connection. Please check your network and try again," which informs users that their device lacks internet connectivity and guides them to verify their network settings. Additionally, the system handles connection timeout scenarios that occur when network requests exceed the predefined timeout duration of twenty seconds. In such cases, users receive the message "Connection timeout. Please check your internet connection and try again," indicating that while a network connection may exist, the request could not be completed within the expected timeframe. These error messages are displayed consistently across all authentication operations including user registration, login attempts, password reset requests, and Google sign-in procedures. The network connectivity check occurs as the first validation step in the authentication flow, preventing unnecessary API calls to Firebase Authentication services when connectivity is unavailable, thereby improving application responsiveness and providing immediate feedback to users. This approach ensures that users understand the root cause of authentication failures related to network issues and are guided toward resolving connectivity problems before retrying their authentication attempts.

## Figure 1.1.5
### Test Case 5: Invalid Email Address

Test case five addresses the client-side validation mechanism for email address format verification that occurs before any authentication request is transmitted to the server. The system implements email format validation using a regular expression pattern that checks for proper email structure, ensuring that the input contains a valid local part followed by the at symbol and a valid domain name with appropriate top-level domain. This validation occurs immediately when the user interacts with the email input field and is enforced during form submission, preventing invalid email formats from reaching the authentication service. When an invalid email format is detected, the client-side validator intercepts the input and displays the error message "Please enter a valid email" directly below the email input field, providing immediate visual feedback to guide the user toward correcting the input error. The validation is performed synchronously without requiring network communication, which means users receive instant feedback about format errors without experiencing network latency or unnecessary API calls. This approach improves user experience by catching obvious input errors early in the interaction flow and reduces server load by filtering out invalid email formats before they reach the Firebase Authentication service. The email validation regex pattern specifically checks for alphanumeric characters, hyphens, periods, and underscores in the local part, followed by a valid domain structure with at least one dot separating the domain name from the top-level domain, which must be between two and four characters in length. This comprehensive validation ensures that only properly formatted email addresses proceed to the authentication request phase, while malformed inputs are caught and corrected at the client level, supporting both user experience and system reliability.

These comprehensive error handling mechanisms ensure that users receive appropriate feedback regardless of the specific reason for authentication failure, supporting both user experience and system reliability. The layered approach of client-side validation for format errors and network-level checks for connectivity issues creates a robust authentication flow that guides users through successful authentication while preventing unnecessary server requests and providing clear, actionable error messages at each stage of the process.
